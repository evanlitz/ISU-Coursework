# CS417 Assignment 2: Automated Test Generation with EvoSuite

**Course**: CS417 – Software Testing, Iowa State University

## Overview

Comparison of **EvoSuite**-generated tests against manually written tests on a deliberately faulty `PrimeNumberFinder` implementation. The assignment demonstrates the strengths and limits of automated test generation and highlights fault classes that automated tools miss.

## Faults in the SUT

`Q6/PrimeNumberFinder.java` contains multiple seeded faults:

| Method | Fault |
|--------|-------|
| `computeSumOfPrimes()` | Only sums elements when list size > 1; otherwise returns the first element — incorrect for single-element lists |
| `computeSumOfPrimes()` | Missing null guard — throws `NullPointerException` on null input |
| `isPrime()` | Returns `true` for 7 incorrectly due to a flawed divisibility check |
| `findPrimes()` | Uses `<` instead of `<=` for the upper bound — silently excludes the upper boundary value |

## Test Suites

### Q5 — EvoSuite Auto-Generated Tests
`PrimeNumberFinder_ESTest.java` is the test class generated by EvoSuite with scaffolding. EvoSuite targets structural coverage and generates tests that exercise many code paths, but may not detect all semantic faults (e.g., the off-by-one in `findPrimes`).

### Q6 — Manual Test Suite
`PrimeNumberFinderTest.java` contains 19 manually written JUnit tests targeting specific fault hypotheses. Results: **6 failures and 2 errors**, exposing the `NullPointerException`, single-element sum bug, incorrect prime detection for 7, and the upper-bound exclusion.
